Streaming STT instead of batch transcription
Browser audio is streamed continuously over WebSocket to Deepgram, so the backend receives partial/final transcripts without waiting for a full recording.

AudioWorklet-based microphone capture
The frontend uses AudioWorklet to capture and send small PCM audio frames from the browser with low overhead.

WebSocket transport
Browser-to-backend audio uses a persistent WebSocket connection, avoiding repeated HTTP request setup per audio chunk.

Interim transcription results
Deepgram interim transcripts are enabled, so the UI can show what the user is saying while speech is still happening.

Endpointing / speech-final handling
Deepgram endpointing helps detect when the user has stopped speaking, reducing the delay before the AI starts processing a turn.

Async FastAPI backend
The backend uses async functions, WebSockets, and non-blocking HTTP calls so STT, LLM, and TTS work do not block the server loop.

Fast-path intent handling
Common replies like “yes,” “yep,” or “I have time” bypass the full LLM path and return predefined next-step responses with near-zero LLM latency.

LangGraph state routing
The conversation is split into smaller stateful nodes, so each LLM call is focused on the current stage instead of processing the whole call flow every time.

Small, structured prompts
Supervisor and node prompts are constrained to short responses and structured outputs, reducing token count and model latency.

Fast LLM backends
The project supports Groq and Gemini models for quick intent routing and response generation.

Streaming / cached TTS
Cartesia TTS is used when configured, and common phrases are pre-generated and cached in memory.

Prewarmed common audio
Greeting and frequent demo responses are cached during startup, making early call turns play almost instantly.

In-memory audio cache
Generated speech audio is stored briefly, so repeated phrases do not need another TTS call.

Immediate browser playback
The frontend starts playing the returned audio URL as soon as the backend provides it, reducing perceived wait time.

Minimal local demo stack
The current demo avoids Telnyx, Redis, PostgreSQL, tunnels, and other full production services, which keeps the local interaction path short.
